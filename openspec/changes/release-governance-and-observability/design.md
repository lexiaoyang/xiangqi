## Context

发布治理与可观测性涉及客户端、账号/业务服务与运营后台协同，属于跨模块变更。当前相关流程存在口径不一致、异常恢复能力弱、可观测性不足等问题，需要在实现前统一技术决策与边界。

## Goals / Non-Goals

**Goals:**
- 每次发布具备可追溯门禁记录与审批链路。
- 发布异常在 5 分钟内被发现并触发处置。
- 高风险发布支持自动回滚。

**Non-Goals:**
- 不重写现有 CI/CD 平台。
- 不引入新的商业 APM 产品。

## Decisions

- 门禁采用“必过检查 + 风险分级审批”双层策略。
- 可观测指标统一为错误率、延迟、吞吐、资源占用四大类。
- 金丝雀分阶段放量并在每阶段执行自动健康评估。

## Risks / Trade-offs

- [门禁过严拖慢发布] → 按风险等级差异化门禁项。
- [告警噪音过高] → 结合基线与抑制规则优化告警。
- [自动回滚误触发] → 增加人工确认阈值与灰度窗口。
