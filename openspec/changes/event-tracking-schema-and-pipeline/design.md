## Context

事件埋点规范与数据管道涉及客户端、账号/业务服务与运营后台协同，属于跨模块变更。当前相关流程存在口径不一致、异常恢复能力弱、可观测性不足等问题，需要在实现前统一技术决策与边界。

## Goals / Non-Goals

**Goals:**
- 核心事件可用率达到 99.5% 以上。
- 事件字段定义单一来源，跨团队口径一致。
- 异常事件可在 10 分钟内告警并可重放。

**Non-Goals:**
- 不在本次实现全量历史事件回灌。
- 不接入第三方 CDP 深度自动化能力。

## Decisions

- 事件名采用 kebab-case，字段采用 snake_case，附带 schema_version。
- 网关执行 JSON Schema 校验，不通过事件进入死信流。
- 流处理层按 event_time 分区写入，保证下游可追溯。

## Risks / Trade-offs

- [客户端旧版本持续上报旧格式] → 兼容窗口 + 双写解析器过渡。
- [高峰时段管道积压] → 增加分区并设置消费滞后告警阈值。
- [敏感字段泄露] → 网关强制脱敏与字段白名单审计。
