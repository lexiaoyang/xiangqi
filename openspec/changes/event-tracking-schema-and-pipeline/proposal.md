## Why

当前事件字段命名不统一、投递链路不稳定，导致分析口径不一致和数据丢失。需要统一埋点 schema 与管道治理，支撑运营与增长决策。

## What Changes

- 定义统一事件命名、公共字段、业务字段与版本治理规范。
- 建设客户端采集、网关校验、流处理入仓的标准化管道。
- 新增事件质量校验、重放补偿与死信处理机制。
- 提供事件字典与变更审批流程。

## Capabilities

### New Capabilities
- `event-tracking-pipeline`: 事件埋点规范与数据管道相关能力定义与交付标准。

### Modified Capabilities
- 无。

## Impact

- 客户端埋点 SDK 需要按统一 schema 发送事件。
- 数据网关需新增字段校验、脱敏与拒绝策略。
- 数仓与 BI 报表需要切换到新主题表。
