## Why

当前项目已具备基础可玩性，但距离“可稳定上线并持续商业化”仍存在明显缺口：账号、云存档、支付变现、运营系统与线上稳定性能力不足。为缩短从原型到收入产品的路径，需要发起一次面向商业化上线的系统性建设变更。

## What Changes

- 新增账号与用户数据基础能力：游客/正式登录、用户档案、云存档与跨设备同步。
- 新增商业化能力：会员订阅、内购商品、权益发放、订单与补偿链路。
- 新增运营能力：任务、签到、活动、公告与基础排行榜。
- 新增数据与监控能力：埋点字典、行为漏斗、崩溃监控、性能与发布观测。
- 新增安全与上线保障：风控规则、灰度发布、回滚机制与客服反馈闭环。
- 对现有对局系统进行可运营化增强：新手引导、推荐解释、关键复盘节点与留存触发点。

## Capabilities

### New Capabilities
- `user-account-and-cloud-profile`: 用户登录、档案与云端进度同步能力。
- `commerce-subscription-and-iap`: 订阅与内购支付、订单管理、权益发放能力。
- `operations-liveops-system`: 任务签到活动公告与排行的运营后台能力。
- `telemetry-and-release-governance`: 埋点监控告警、灰度发布与回滚能力。
- `retention-onboarding-and-challenges`: 新手引导、每日挑战与复盘激励能力。

### Modified Capabilities
- `xiangqi-analysis-and-replay`: 从基础复盘升级为可运营化复盘（关键节点、解释与策略反馈）。
- `xiangqi-ai-difficulty-engine`: 强化难度分层稳定性，支持商业化版本中的推荐权益分层。

## Impact

- 代码影响：前端 H5、后端服务、支付模块、用户系统、运营后台、数据看板。
- API 影响：新增认证、档案、订单、权益、任务活动、埋点上报等接口。
- 数据影响：新增用户、订单、权益、任务进度、行为日志等核心表与索引。
- 运营影响：上线后需由运营后台配置活动、奖励与通知流程。
- 风险影响：支付与账号链路需重点压测与容灾，避免上线后收入与数据损失。
