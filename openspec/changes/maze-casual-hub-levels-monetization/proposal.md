## Why

当前迷宫为「单页全能」形态，缺少休闲手游常见的**大厅—全屏对局**分层、**长线关卡推进**与**养成式解锁**节奏；同时视觉与信息架构仍偏工具感，不利于后续接入**内购/广告/活动**等商业化模块。本变更将产品明确为「手机内置感」的休闲小游戏：首页聚合入口与数据，对局进入沉浸式全屏；关卡制（目标 1000 关）承载难度爬升；阻碍与道具分阶段解锁；UI 对齐可盈利的轻度休闲品类心智。

## What Changes

- **应用壳层**：引入「大厅 / Hub」与「全屏游戏页」两种布局形态；从 Hub 进入对局后隐藏非必要导航，对局结束返回 Hub。
- **关卡战役**：以「关卡号 1…1000」为主进度轴；每关绑定迷宫参数（尺寸、随机种子、允许的机制标签集合）；难度随关卡单调或非严格单调上升；支持关卡地图/列表与解锁规则（通关解锁下一关）。
- **阻碍与工具**：定义可扩展的「阻碍模式」目录（如限时、迷雾、单向门、动态障碍等）按关卡或章节逐步开放；定义「工具/道具」目录（如提示一步、撤销、破墙一次等）按进度或货币解锁，并在对局内有限使用。
- **商业化向 UI**：统一「软货币/体力条/关卡星数/章节宝箱/商店入口」等占位与动效规范；不要求首版真实支付闭环，但界面与数据模型需预留 IAP/广告位。
- **数据与存档**：关卡进度、解锁状态、货币与道具库存持久化（本地优先，可与既有 `server/` 或 cloud-save 变更对齐）；排行榜可按「关卡维度」扩展。

## Capabilities

### New Capabilities

- `maze-casual-app-shell`：Hub 首页布局、功能入口、数据总览、进入全屏对局与返回；移动端安全区与全屏 API 策略。
- `maze-level-campaign`：1000 关关卡模型、难度曲线、关卡选择与通关状态；关卡与迷宫生成的绑定规则。
- `maze-mechanics-unlock`：阻碍模式与工具的编目、解锁条件、对局内消耗与效果；与关卡战役的交叉引用。
- `maze-casual-monetization-ui`：休闲变现向视觉与组件规范（货币、体力、星级、弹窗层级、奖励飞入等）；与壳层、战役的界面接缝。

### Modified Capabilities

- （无）——既有 `openspec/specs/xiangqi-*` 为象棋能力域，与本迷宫休闲战役无直接需求继承；不在此变更下做 delta，以免混淆能力边界。

## Impact

- **前端**：`src/App.tsx` 将拆分为多路由/多视图或等价状态机；新增关卡数据层、解锁与库存状态机；样式体系向「章节化 + 全屏 HUD」演进。
- **服务端（可选）**：关卡配置 CDN 化或版本化包；进度与防作弊若上云需与 `cloud-save-and-cross-device-sync` 等变更协调。
- **内容生产**：1000 关可「程序化生成 + 人工抽检」或「批量数据文件」；需内容管线说明（见 design）。
- **测试**：E2E 覆盖 Hub→Play→结算→回 Hub；关卡解锁与道具边界单测。
