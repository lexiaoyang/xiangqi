## Context

仓库当前为 Vite + React 迷宫 H5，已具备多机制场景（收集/洋流/传送门）、缩放、本地/简易服务端战绩。用户目标转向「开心消消乐式」关卡制长线产品形态，并强调**手机内置小游戏**体验与**可商业化外观**。

## Goals / Non-Goals

**Goals:**

- 双阶段 UI：**Hub**（选功能、看数据、进关）与 **Play**（全屏对局 + HUD）。
- **1000 关**可寻址进度（`levelId` 1…1000），每关可复现（种子 + 参数），难度总体随关卡上升。
- **阻碍**与**工具**可插拔注册，按关卡区间或玩家等级**逐步解锁**。
- UI 规范对齐轻度休闲：**软货币、体力、星级、章节、商店入口**等占位完整，动效与层级统一。

**Non-Goals（首版可不实现，但设计预留）：**

- 真实 IAP/广告 SDK 接入与合规审查流程（仅预留接口与 UI）。
- 服务端反作弊与关卡热更新（可列为二期）。
- 1000 关全部手摆迷宫（默认接受程序化 + 关键节点人工校验策略）。

## Decisions

1. **路由模型：Hub / Play 两态**  
   - **选型**：优先使用 React 状态机 + `view: 'hub' | 'play'`（或 React Router 若已引入）。  
   - **理由**：当前无路由依赖，状态机改动面小；若后续深链接分享关卡再引入路由。  
   - **替代**：React Router — 利于分享 `?level=42`，但增加包体与 SSR 无关复杂度。

2. **1000 关内容来源：程序化为主**  
   - **选型**：`levelId` → 确定性参数函数 `f(level)`：`gridSpec`、`mechanicMask`、`obstacleMask`、`timeLimitSec?`、`starThresholds(steps, time)`。  
   - **理由**：维护成本可控；与「每关可复现」一致。  
   - **替代**：1000 个 JSON 关卡文件 — 体积与构建管线成本高；可作为后期「精品关」补丁包。

3. **难度曲线：分段函数 + 上限钳制**  
   - **选型**：按章节（如每 50 关）提升迷宫尺寸/机制密度；`expert` 级尺寸仅在 800+ 关出现；单关步数/时间阈值用于星级。  
   - **理由**：避免前期劝退与后期无解；便于 A/B 调参。

4. **阻碍与工具：注册表 + 解锁矩阵**  
   - **选型**：`ObstacleKind` / `ToolKind` 枚举 + `unlocksAtLevel(level)` 或 `unlocksAtChapter(ch)`；对局内 `ToolUse` 消耗软货币或关卡内免费次数。  
   - **理由**：与关卡公式正交，便于加新阻碍而不改旧关公式（通过 mask 关闭未解锁项）。

5. **持久化：本地 IndexedDB 或 localStorage 分层**  
   - **选型**：`progress.maxUnlockedLevel`、`perLevelStars`、`inventory.tools`、`wallet.softCurrency`、`stamina` 等键；体积超限时用 IndexedDB。  
   - **理由**：对齐「手机小游戏」离线可玩；服务端同步后续对接 cloud-save 变更。

6. **「能赚钱的小游戏」外观：组件与令牌**  
   - **选型**：设计令牌（圆角、阴影、渐变、粒子 sparingly）、**顶部资源条** + **底部安全区 CTA** + **胜利/失败全屏卡**；禁用廉价闪烁滥用。  
   - **理由**：可测试、可维护；符合应用商店常见休闲 UI 范式。

## Risks / Trade-offs

| 风险 | 缓解 |
|------|------|
| 程序化 1000 关出现无解或过难 | CI 关卡求解器抽检；关键章节人工 seed 覆盖；热修配置表 |
| 全屏 API 浏览器差异大 | 渐进增强：`requestFullscreen` 可选；失败则「伪全屏」CSS `100dvh` |
| 双货币/道具状态爆炸 | 首版单一软货币 + 少量工具；文档规定扩展点 |
| UI 过重影响低端机 | `prefers-reduced-motion`；Play 页懒加载非关键装饰 |

## Migration Plan

1. 首版上线不改变现有「练习/挑战」用户数据的键名：新增 `campaign:*` 命名空间，避免覆盖 `maze:runs:v1`。  
2. 若启用服务端关卡配置：版本号 `campaignPackVersion`，客户端缓存 TTL。  
3. 回滚：特性开关 `VITE_CAMPAIGN_ENABLED` 关闭时回退单页迷宫（可选）。

## Open Questions

- 星级规则：仅步数 / 步数+时间 / 是否收集物——是否随 `mechanic` 变化？  
- 失败惩罚：扣体力 vs 无限重试——是否分「休闲」「挑战」双轨？  
- 是否需要关卡地图「路径节点」美术（类似消消乐大地图）首版即做，还是先用列表 MVP？
