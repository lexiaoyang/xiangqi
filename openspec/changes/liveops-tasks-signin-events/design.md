## Context

运营任务、签到与活动事件涉及客户端、账号/业务服务与运营后台协同，属于跨模块变更。当前相关流程存在口径不一致、异常恢复能力弱、可观测性不足等问题，需要在实现前统一技术决策与边界。

## Goals / Non-Goals

**Goals:**
- 运营可在不发版情况下配置新活动。
- 任务进度计算与领奖行为一致可追溯。
- 签到补签、断签策略清晰可配置。

**Non-Goals:**
- 不实现复杂营销自动化编排。
- 不覆盖跨游戏联动活动。

## Decisions

- 活动配置采用版本化 JSON，并按活动窗口生效。
- 任务进度采用事件驱动累计，避免高频全量扫描。
- 签到奖励支持固定与随机池两种发放策略。

## Risks / Trade-offs

- [配置错误影响大面积用户] → 上线前执行静态校验与灰度。
- [进度重复累加] → 事件去重键 + 幂等处理。
- [活动切换时区问题] → 全部按服务器时区并展示本地化文案。
