## Context

云存档与跨设备同步涉及客户端、账号/业务服务与运营后台协同，属于跨模块变更。当前相关流程存在口径不一致、异常恢复能力弱、可观测性不足等问题，需要在实现前统一技术决策与边界。

## Goals / Non-Goals

**Goals:**
- 用户在任意登录设备上都可恢复最近一次有效进度。
- 常规同步延迟控制在 3 秒以内。
- 冲突场景有明确可追溯决策。

**Non-Goals:**
- 不实现多人实时协同编辑同一存档。
- 不覆盖历史版本的可视化时间线。

## Decisions

- 采用“乐观并发版本号 + 内容哈希”判定冲突，避免全量锁表。
- 默认以最新完成对局时间为主版本，并保留被覆盖快照。
- 离线队列按时间顺序重放，失败项进入死信队列等待人工排查。

## Risks / Trade-offs

- [不同端版本不兼容] → 引入存档 schema_version 与迁移器。
- [高频同步增加成本] → 分层触发策略并限制最小间隔。
- [冲突策略误判] → 保留回滚快照并允许用户手动恢复。
